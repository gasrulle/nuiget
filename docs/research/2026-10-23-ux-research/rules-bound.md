# nUIget design rules bound to measured numbers (VS Code 1.142.0 probe)

Research dimension: **rules-bound** · 2026-10-22 · repository read-only. Every number below comes from the probe output
in `probe/out/` (JSON, or a pixel scan of a probe PNG, which is labelled as one). The tables are generated by
`rb-tools/bind.py` from that output. Only the prose is hand-written, and it repeats numbers from those tables. Data:
`research/rules-bound.json`.

## 0. Answer first

- **The 72 DS rules today:** 37 fail, 8 pass, 27 cannot be
  measured from this probe. The failures cluster in four areas: control and row heights (24 px controls vs 25/26,
  rows 79/24 vs 72/22), asymmetric insets, the type ramp (14.95 px/700 details title, 9.39 px sidebar badge), and
  colour roles (icon glyphs, disabled text, the row check mark, high-contrast tabs).
- **The probe rendered classic chrome, not Modern UI.** Section 2 has the evidence: 22 px pane headers set 11 px/700
  uppercase, square 35 px editor tabs, and no gutter around the side bar. One correction to the task premise: the
  **12 px quick-input radius is the classic value.** Ungated `quickInput.css` uses `cornerRadius-xLarge` (12 px),
  and `.modern-ui` overrides it to `cornerRadius-large` (8 px). The 26 px buttons and selects do not tell the two
  looks apart, and neither do the codicons, which cannot be assessed from this probe. **The design should target the
  classic 1.142.0 look.** That look is the only one measured here.
- **V1, V2, V4 and V5 are reproduced in numbers** (section 4). For **V3 the state is missing.** No
  `main-installed-all` with a provisional badge was captured. The cause is visible anyway: the main panel's
  `.nuiget-section-actions` slot sits at x 931 = list right edge, with width 0. The sidebar's Update all button ends
  at 300 = the sidebar's right edge.
- **Where the probe corrects design-rules.md** (section 6):
  - The Extensions search box renders 26 px (PNG). The 28 px that design-rules cites belongs to `.search-box`, which
    is not the rendered control. The box is a `SuggestEnabledInput` laid out at 20 px
    (`extensionsViewlet.ts:743`, `suggestEnabledInput.ts:488`) with a 1 px border (`suggestEnabledInput.ts:319`). The
    remaining 4 px are not explained by the local sources.
  - The Settings input box is 25 px.
  - Pane-header actions are 20 px (padding 2), beside the 22 px row and title actions.
  - The Extensions row action keeps a 6 px end inset, not 12.
  - The quick-input shadow is `0 0 20px rgba(0,0,0,0.15)`.
  - The classic list paints its focus outline after a mouse click.
  - The details title weight is 700, not 600.
  - Three rule premises are design choices, not workbench measurements, and should be labelled as such: the {4, 8}
    block-gap set (DS-GRID-2), symmetric insets (DS-INSET-2) and keyboard-only focus (DS-FOCUS-3). The Extensions
    view measures block gaps of 5 and 10, and its header padding is 5/12/6/20.
- **New failures the probe exposes:**
  - nUIget animates while the host has `body.vscode-reduce-motion` set (DS-MOTION-2).
  - Sidebar section-header borders are inverted against the workbench (DS-DIVIDER-1).
  - Divider lines are `#313131` (`widget.border`), not `#2b2b2b` (`settings.headerBorder`) (DS-DIVIDER-4, PNG greys).
  - The row check mark border uses the divider colour, not `checkbox.border`.
  - Inactive tab text and icon glyphs read `rgba(255,255,255,0.7)` in Dark High Contrast.
  - The details tab label sits at x 9, not 16 (DS-INSET-1).
  - The sidebar view title shows 6 actions; Explorer shows 4.
  - Control radius is 2 px vs the workbench's 4 px. No DS rule covers control radius; it should get one.
- **Token availability:** 1.142.0 exports `--vscode-spacing-*` (14 keys), `--vscode-cornerRadius-*` (6),
  `--vscode-fontSize-*` (8), `--vscode-fontWeight-*` (regular, semiBold), `--vscode-codiconFontSize*` (2),
  `--vscode-strokeThickness` and `--vscode-bodyFontSize*` (3) to webviews. All are identical in all six themes.
  **No `--vscode-lineHeight*` exists.**

## 2. Modern UI or classic (task B)

**Verdict: classic.** The 1.142.0 workbench the probe measured did not render Modern UI.

- **Pane headers:** 22 px high, titles 11 px/700/uppercase (`extensions.json` pane_headers[0] and [3]). Modern UI
  draws 28 px headers with 12 px/600 capitalized titles.
- **Editor tabs:** square (`borderRadius 0px`), 35 px strip, carrying the `tab-border-top` class (`tabs[0]`, `tabs[1]`).
  Modern UI draws connected or pill tabs with a 4 px radius.
- **No floating panels:** the side-bar content starts at x 48, right after the 48 px activity bar, and the editor
  container starts at x 348 = 48 + 300. Modern UI's default density draws floating cards with outer gutters.
- **Screenshots agree:** `probe-workbench-extensions.png` shows "INSTALLED" and "RECOMMENDED" in bold capitals and a
  square tab with a blue top border. `probe-sidebar-sections.png` shows the same for the nUIget view title.
- **The quick input's 12 px radius points to classic, not Modern UI.** In the pinned source, ungated
  `quickInput.css:12` is `var(--vscode-cornerRadius-xLarge)`, and the theme variables give xLarge = 12px. The
  `.modern-ui` rule at `roundedCorners.css:192-193` sets `cornerRadius-large` = 8px.
- **Not discriminators:** the 26 px buttons and selects come from ungated `button.css` and `selectBox.css`.
- **Limits:** the workbench `body` class was not captured, so there is no direct `.modern-ui` check. The codicon
  redraw cannot be assessed: glyph paths are not probe fields, and the codicon font ships with the build whatever
  the setting.
- **Unverified:** why the setting resolved off. `src/test/ui/settings.json` does not set it, and design-rules records
  an experiment-controlled default of `true` from release/1.139.

**Design target:** the classic numbers in section 3. Modern UI values (28 px headers, 12/600 titles, 8 px overlay
radius) remain CSS-read only.
