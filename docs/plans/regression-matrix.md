# Regression coverage matrix

Plan item P10.0a (owner, 2026-10-17). One row per feature, state, keyboard path, command, menu placement and setting
that 2.0.0 ships, from `docs/ux/interaction-model.md` and `package.json` `contributes`, with the test that asserts it.
`npm run check:matrix` (`scripts/check-regression-matrix.mjs`, run by CI's docs step) fails unless every row has an id,
a kind and a status, and every cited file exists and declares the cited title.

How to read and maintain it:

- **covered**: the cited test asserts the behaviour (not only that the surface renders), at any layer: `ui` (ExTester,
  `src/test/ui/v2`), `e2e` (extension host, `src/test/e2e`), `harness` (two-surface harness, `src/test/harness`) or `unit`
  (Vitest). A row covered by a unit test alone is covered.
- **gap**: no test asserts it; the file and title name the test to write, and a tracker row `P10.0b`… writes it. When it
  is green locally and in CI, the row becomes `covered` (the check then requires the title in the file).
- **manual-credentials**: needs a real credentialed package source, which CI does not have. The cited test covers the
  automated part; the row is checked by hand before a release (`docs/release-checklist.md`, P10.1).
- Ids are never reused or renumbered; a new row takes the next free id.
- Not rows: what 2.0.0 does not ship (recent searches, hover prefetch, Collapse all / Expand all, ArrowLeft/ArrowRight
  between the details tabs; ledger V1-V5 and the parity audit's open rows), the manual screen-reader pass P7.4
  (2.0.1), and the header "Restore project(s)" that interaction model §5 names but no surface renders (parity audit,
  critic). The `data-testid` hooks of §8 are held by `src/test/lint/interaction-model-testids.test.ts`.
