2026-11-27, UX-P5.2b, design-advisor opening ruling. Question: is the item a design round with a fork, or can the forms be ruled
directly by D22; if directly, the forms, named states (and capture literals), rules and measurements, files, push plan and VERIFY lines.
Answer, verbatim:

> DECISION: Ruled directly; no design round and no stop for a pick. The forms follow from primitives and rules already ruled (DS-ROW-5 names the Deprecated label badge; the `.nuiget-details-notice` banner form is measured since UX-P5.fix-7; the selector's "(installed)" annotation is the option form). One part of the plan row is not built here: an update row cannot say it "fixes" an advisory, because the row has no knowledge of the target version. That goes to the planning session as a row.
>
> WHY:
> - **Rows.** DS-ROW-5 (`design-system.md:76`) already lists "Deprecated" among a comfortable row's label badges, so the row form is not a fork. Its tone follows the product's one state-badge precedent, "Unsupported" (`tone="warning"`, no glyph; `InstalledProjectSection.tsx:115`). The glyph stays reserved for the severity scale (DS-HEIGHT-10), so a "Deprecated" pill never reads as a Moderate advisory.
> - **Details.** Deprecation is a fact of the chosen version and arrives with `package/metadata`. Placing it in the facts as the notice banner moves no header when metadata lands, and the `facts-banner` clause already measures that box (glyph 20, top 0, next block 12).
> - **Selector.** A native option carries text only. The microcopy lint admits one trailing parenthetical on an option (gotcha row "A label, a sentence or an ellipsis"), which is the "(installed)" form at `DetailsPane.tsx:203`.
> - **Updates.** `PackageUpdate` (`src/protocol/domain.ts:98-106`) has no vulnerability or deprecation field for `latestVersion`, and `vulnerableVersions` is asked only by the details slice. A row that says "fixes" would claim what it does not know ("Empty is not unknown").
> - **Delegation.** D22 and the in-product precedents settle each form, so nothing here is a taste fork for the owner.
>
