> WHY:
> 1. Home. `StoreProvider.tsx:27-37` nests `OpsProvider` innermost, under `InstalledProvider`, `UpdatesProvider` and `AllProjectsProvider`. > 2. Event-order facts, confirmed in the host:
>    - Order: `settleOperation` announces, then invalidates (`handlers.ts:162-163`). So per webview the wire order is `ops/completed`, then `resources/invalidated` in the same host turn, then the response.
>    - Coalesced: yes. The `project` and `metadata` calls of `invalidateAfter` (`handlers.ts:245-247`) merge into one event (`QueryCoordinator.ts:215-221`; test `QueryCoordinator.test.ts:233` "invalidate coalesces into one event"). If a flush was already pending, the operation's keys join that event. Either way the first `resources/invalidated` after an `ops/completed` is the operation's.
>    - An event always follows an ok edit: the arm predicate (`edit.ok` and a `packageId`) is a subset of `affectedScope` (`handlers.ts:218-236`), and the flush fires even with zero keys (`:420-427`). That makes "drop when not named" timer-free.
>    - A key never computed is not listed: `invalidate` walks `this.entries` only (`:192`), and an entry is created only by `query` (`:156`, `:261-268`). Entries are never deleted before `dispose`, so keys of other projects and of the other prerelease flag are listed too. "Listed" must therefore be compared with the slice's current key, not with "any key of the project".
>    - `projects` is always named after an ok edit: a `project` scope matches the `projects` key (`scopes.ts:66`) and its entry exists from activation (`extension.ts:186`). Both All Projects streams re-ask on it (`allProjects.tsx:184`, `:188`), and the updates fan-out also computes per-project `updates:<p>|flag` through the coordinator (`Catalog.ts:233`, `:383`).
> 3. A level test ("listed and not requesting") would therefore end an All Projects row at once. The end must be an edge: the list's unanswered flag going true → false after the listing. An earlier request still in flight is aborted by the re-ask and applies nothing (`useResource.ts:75-82`, `allProjects.tsx:224`, `:320`), so the edge is the post-listing settlement, answer or error.
> 4. Response-first arming. With the order above, an outcome whose first record is the response means this surface never received the event.
