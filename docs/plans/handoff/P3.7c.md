> DECISION: The sidebar Installed pane under All Projects becomes one `Listbox` tree with `groups` (density `compact`): folder rows at level 1 and project rows at level 2 when the workspace has several folders, project rows at level 1 otherwise, package rows under them, message leaves for an empty or unsupported project and a banner above the tree for a failed one, as `InstalledTab.tsx:180-260` does. (a) A sidebar group row is a compact tree row: 22 px, the `level` variant of `SectionHeader` (13 px / 600 / no transform), the compact band (inset M 4 / C 0, radius M 4 / C 0, `list.hoverBackground`), chevron at the pane header's start x plus (level − 1) × `workbench.tree.indent`, title 16 + 4 after it, the count badge and, before it, the provisional badge ending 6 px inside the band in both looks, no divider between group rows; package rows indent by (level − 1) × indent too. (b) A single project renders no group row: the flat listbox stays exactly as today. (c) One new state `sidebar-all-projects` (dark-modern 300 and classic 300) reached through All Projects plus `@installed`; three helpers amended, no `pending` flip. (d) Two tests rewritten in place, `sidebar-installed-list-<name>` leaves §8, the three P3.7c baseline entries go with the rules they name. (e) No `*Props` diff: the primitives already carry everything; the project-path tooltip is dropped.
>
> WHY: D48 and the model (§4 `:78-83`: "in the sidebar each pane stays a pane and its list is one grouped list with a group row per project") fix the structure; the gotchas fix what a tree may hold (treeitems only, message leaves, banners above, skeleton in `empty`). The row anatomy follows the workbench's trees inside a pane: a tree row is 22 px in both looks (DS-HEIGHT-2, `explorer.json list_rows[0]`), its band inset 4 / radius 4 under Modern UI (T-2, `design-system.md:378`), children indented by `workbench.tree.indent` (the sidebar already reads it into `--nuiget-tree-indent`, `SidebarView.tsx:112`), and a group label with a count badge at its end is the SCM view's resource-group row (bold label, badge; not in the probe, named as unverified) and the main panel's own level-2 project row (`InstalledTab.tsx:216`, `variant: 'level'` = 13/600/none, X36 one anatomy); a pane-header-typed row (12/600 capitalised, 28) inside a pane is a nested pane header, which no workbench tree draws. A single root is not a row in the Explorer (the pane header names it), and here the view title names the project; the main's single project adds a Direct packages group only because Transitive follows it, which the sidebar has not. The helpers must read what the rules say and nothing less: DS-INSET-1 reads every `.nuiget-section-title` and `.nuiget-row-name` against one x (`measure.ts:1100, 3300-3305`) and knows no level; DS-HEIGHT-2 excludes group wrappers (`:1125`); DS-INSET-3 `sidebar` reads pane headers and row actions only (`:2192-2199`); the new state exercises all three (design trigger 6), so they are amended in this item, and DS-TYPE-5 `sidebar` already targets the level variant at 13/600/none (`:2776`). The Listbox estimates every group row at the pane-header token (`Listbox.tsx:12-16, 187`); a 28 px estimate for 22 px rows is the P2.1e sizer drift, so the compact estimate is the compact row.
