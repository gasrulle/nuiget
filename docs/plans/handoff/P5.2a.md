> DECISION: A = option 2, as a synchronous read of data already loaded: no wait, no timer, and `package/versions` starts no download. B = option 3 in the `liteLookup` form: a cached lookup in `feedClients.ts` over the existing, unused `metadata` cache kind and key (10 min, memory only), fed by a new leaf-only `RegistrationClient.deprecation` read that tells found, missing and failed apart. >
> WHY:
> - **A.** `package/versions` gates the details selector (`src/webview/shared/store/details.tsx:246-251`) and the suggestion install (`src/webview/main/features/search/useSearchTyping.ts:115`). Any wait on a 20 MB data set delays both and lands on N93's reach. `package/metadata` follows the selector and already waits for the data unbounded (`src/core/catalog/Catalog.ts:543`), so it starts the load. ADR-009 d.1's "absent whenever the data is unknown" covers "not loaded yet". A timer is also wrong for the harness's fake clock.
> - **A, source set.** ADR-009 d.1 says "the vulnerability data of the allowed sources", and the sentence before it defines allowed as policy-allowed for the id. `Catalog.ts:543` and the enricher pass `resolved`. The ADR is frozen, and D39 names the contract bundles, so this item follows the ADR: `allowed`. Under source mapping the selector can therefore read unknown where the details list advisories; that is honest (absent = unknown) and goes to the planning session for P5.10a.
> - **B.** Option 1 is out on evidence. The coordinator keeps 200 values (`src/core/queries/QueryCoordinator.ts:108`, eviction at `:393-405`); one `metadata:` value per id and source from a large list would evict `installed:` and `updates:` values. Option 2 costs two requests per id on every ask.
> - **B, why a new read.** `RegistrationClient.metadata` answers `undefined` for unknown, not allowed and unreachable alike (`src/core/feeds/registration.ts:139-157`), and its fallback scans every page of the index.
