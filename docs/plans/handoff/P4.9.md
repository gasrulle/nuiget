> WHY:
> - **X32 breaks ADR-009 d.3 as written.** d.3 (`/Users/mattias/github/nuiget/docs/adr/009-catalog.md:11`) says `upgrade` is "present only when an evaluation has started". `Catalog.installed` (`/Users/mattias/github/nuiget/src/core/catalog/Catalog.ts:166-173`) returns `upgrade` as soon as a chunk arrives. With the emit before the walk, a walk that then fails (`:198-207`) gives a chunk plus an `upgrade` with no evaluation. The research verdict cleared d.4 only.
> - **X32 also costs the second surface its provisional rows.** Chunks reach only subscriptions attached at `emit` (`/Users/mattias/github/nuiget/src/core/queries/QueryCoordinator.ts:294-306`), and a joiner gets the final value (`Catalog.ts:170`; d.2, d.3). Today the join window is the `dotnet nuget config paths` spawn (`/Users/mattias/github/nuiget/src/core/project/context.ts:79`). After the move it would be one `readFile` of the project (`/Users/mattias/github/nuiget/src/core/project/inspector.ts:85`) plus a cached probe. The surface that asks second would then wait for the whole evaluation, and the two hard cells of UX-P4.fix-23 (`[hold] … passed 1`) would become a race. Curing that means replaying the provisional to joiners, which is a d.2/d.3 amendment. X32(b) shrinks the same window on every recomputation and leaves user-level configs unwatched (N72). X32(c) is in the evaluator, outside the row's files, and unmeasured.
> - **X33's "warm" has no place to add anything.** d.5 allows warming only after the chain is registered, which is when the chunk emits and the webview asks. The load is already shared and already core-side (`/Users/mattias/github/nuiget/src/core/feeds/vulnerability.ts:95`, `dataFor`), started by the first package of `enrich` in parallel with icons (`/Users/mattias/github/nuiget/src/core/feeds/enricher.ts:54-58`). A trigger in `FeedContexts.resolve` would download the data set for Browse and Updates, which `/Users/mattias/github/nuiget/src/core/catalog/feedClients.ts:48` excludes on purpose. What is new is the bound.
> - **X43 needs no contract change.** The `metadata` chunk kind exists and the reducer merges a second chunk per project (`/Users/mattias/github/nuiget/src/webview/shared/store/allProjects.tsx:130-134`). d.1's "enrichment must not delay the list" fixes the form: the first enrichment is never awaited before the authoritative `project` chunk.
